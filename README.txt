URPAQ INCLUSIVE — САЙТ, ПОРТАЛ ПЕРСОНАЛА И СЕРВЕР
=================================================

СОСТАВ

  index.html          короткая визитка фонда
  foundation.html     полный публичный сайт (три языка: ru / kk / en)
  staff-portal.html   портал персонала
  assets/             клиент API, общий для обеих страниц
  eventum.sql         база данных EVENTUM (PostgreSQL 14+), один файл
  server/             серверная часть на Python (FastAPI)

ЧТО ИЗМЕНИЛОСЬ

  Раньше сайт работал без сервера: портал хранил данные в localStorage браузера,
  файлы — в IndexedDB, а формы просто открывали WhatsApp. Это годилось для показа
  интерфейса, но не для работы: данные видел любой, кто сел за тот же компьютер,
  чистка кеша стирала их без следа, а на другом устройстве их просто не было.

  Теперь всё хранится в базе на сервере. В браузере не остаётся ничего, кроме
  токена сессии в защищённой cookie: ни персональных данных, ни файлов, ни
  настроек интерфейса.

ЗАПУСК

  1. Создать базу:

       psql -h <host> -U postgres -f eventum.sql

  2. Задать пароли (в файле их нет и быть не должно):

       psql -U postgres -c "ALTER ROLE eventum_app PASSWORD '<пароль приложения>';"
       psql -U postgres -d EVENTUM -c "SELECT sec.set_password(
              (SELECT id FROM sec.users WHERE username='admin'),
              '<пароль администратора>', NULL, 'initial', NULL, true);"

  3. Поднять сервер:

       python3 -m venv .venv
       .venv/bin/pip install -r server/requirements.txt
       cp server/.env.example server/.env      # указать DSN и пароли
       cd server && ../.venv/bin/python -m uvicorn app.main:app --port 8000

  4. Открыть http://localhost:8000/ — сайт,
             http://localhost:8000/staff-portal.html — портал персонала.

  Сервер отдаёт и API, и статику: отдельный веб-сервер для файлов не нужен.
  Подробности — в server/README.md.

ДОСТУП В ПОРТАЛ

  Учётные записи создаются в базе без пароля: войти по ним нельзя, пока
  администратор не задаст пароль через sec.set_password() по защищённому каналу.
  Опубликованных паролей в проекте больше нет — прежние демо-пароли лежали прямо
  в этом файле и в коде страницы, то есть были известны всем.

  Требования к паролю (настраиваются в sec.password_policy): не короче 12 символов,
  заглавные и строчные буквы, цифра, спецсимвол; пароль не должен содержать логин
  и повторять пять предыдущих. После пяти неудачных попыток вход блокируется
  на 15 минут.

ЧТО НУЖНО СДЕЛАТЬ ПЕРЕД РЕАЛЬНЫМ ЗАПУСКОМ

  * Заменить пароли ролей CHANGE_ME_* из eventum.sql.
  * Включить TLS (hostssl в pg_hba.conf, sslmode=verify-full в приложении,
    EVENTUM_COOKIE_SECURE=true) — портал работает с данными о здоровье детей.
  * Проверить log_statement = ddl, а не all: иначе пароли попадут в логи базы.
  * Настроить резервное копирование по регламенту из раздела 15 файла eventum.sql
    и хотя бы раз проверить восстановление.
  * Утвердить у юриста политику конфиденциальности, оферту и формы согласий —
    в базе они лежат черновиками (site.legal_documents), и база не даст выставить
    неутверждённый текст как действующий.
  * Для приёма платежей: указать HTTPS-адрес оператора в site.settings.payment_url
    и включить проверку подписи в обработчике webhook. До этого сайт регистрирует
    намерение пожертвовать и открывает WhatsApp администратора, но не подтверждает
    платёж самостоятельно.

  Портал работает с персональными данными несовершеннолетних, включая сведения
  о здоровье. Соответствие закону РК «О персональных данных и их защите» № 94-V,
  в том числе требование хранить базу на территории Казахстана, должен подтвердить
  юрист фонда.
